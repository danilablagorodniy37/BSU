# Weather Data Processing Project

**Module:** CPUF001 Software Foundation
**Assessment:** S1 Development Project

A small command line pipeline written in Python that turns a file of raw daily
weather observations into per-day derived metrics and a human-readable summary
report.

---

## Repository contents

| File | Purpose |
| --- | --- |
| `weather_processor.py` | The Data Processing program. Reads a CSV given on the command line, performs the calculations and writes the output files. |
| `clean_data.py` | Pre-processing script. Validates the raw file and writes a cleaned CSV for the main program. |
| `run_analysis.bat` | Windows CLI script that runs both stages end to end. |
| `run_analysis.sh` | Linux/macOS equivalent of the batch script. |
| `build_exe.bat` | Packages `weather_processor.py` into `dist/weather_processor.exe` with PyInstaller. |
| `data/raw_weather_2025.csv` | A year of raw observations, including deliberately faulty rows. |
| `data/sample_week.csv` | A seven-row clean file for quick tests. |
| `data/weather_cleaned.csv` | Generated by `clean_data.py`. |
| `output/daily_metrics.csv` | Generated per-day results. |
| `output/summary_report.txt` | Generated summary report. |
| `docs/figure1_script.png` | Flowchart of the command line script. |
| `docs/figure2_program.png` | Flowchart of the Data Processing program. |

## Quick start

Run the whole pipeline with the bundled sample data:

```
run_analysis.bat
```

On Linux or macOS:

```
chmod +x run_analysis.sh
./run_analysis.sh
```

Use your own file, and a 14-day smoothing window:

```
run_analysis.bat data\my_observations.csv 14
```

### Running the stages individually

```
python clean_data.py data\raw_weather_2025.csv data\weather_cleaned.csv
python weather_processor.py data\weather_cleaned.csv
python weather_processor.py data\weather_cleaned.csv -o output\metrics.csv -r output\report.txt -w 14
python weather_processor.py --help
```

### Building and running the executable

```
pip install pyinstaller
build_exe.bat
dist\weather_processor.exe data\weather_cleaned.csv
```

Once `dist\weather_processor.exe` exists, `run_analysis.bat` uses it
automatically in place of the Python source.

## Input format

A CSV file with a header row and these six columns:

```
date,temp_max_c,temp_min_c,humidity_pct,rainfall_mm,wind_kph
2025-01-01,8.0,1.7,83.4,0.0,7.8
```

| Column | Meaning | Units |
| --- | --- | --- |
| `date` | Observation date, ISO format `YYYY-MM-DD` | — |
| `temp_max_c` | Highest temperature of the day | °C |
| `temp_min_c` | Lowest temperature of the day | °C |
| `humidity_pct` | Mean relative humidity | % |
| `rainfall_mm` | Total rainfall | mm |
| `wind_kph` | Mean wind speed | km/h |

---

## Calculations

Per day:

* **Mean temperature** — the midpoint of the daily maximum and minimum.
* **Diurnal range** — maximum minus minimum, showing how far the temperature swung.
* **Dew point** — Magnus-Tetens approximation from temperature and humidity.
* **Apparent temperature** — the Australian Bureau of Meteorology "feels like"
  formula, combining temperature, humidity and wind speed.
* **Rolling mean** — a centred moving average of mean temperature over the
  chosen window, which removes day-to-day noise.
* **Rain day / frost day flags** — a day counts as wet at 0.2 mm or more of
  rain, and as a frost day when the minimum falls below 0 °C.

For the whole period:

* mean temperature, mean humidity, total and mean daily rainfall
* counts and percentages of rain days and frost days
* the warmest, coldest, wettest and windiest days
* a least-squares linear trend in mean temperature, reported in °C per month
* a month-by-month table of mean, minimum and maximum temperature, rainfall
  total and number of wet days

## Command line options

```
usage: weather_processor.py [-h] [-o OUTPUT] [-r REPORT] [-w WINDOW] [-q] input

positional arguments:
  input                 path to the input CSV file

options:
  -h, --help            show this help message and exit
  -o, --output OUTPUT   path for the per-day CSV (default: output/daily_metrics.csv)
  -r, --report REPORT   path for the text report (default: output/summary_report.txt)
  -w, --window WINDOW   rolling average window in days (default: 7)
  -q, --quiet           do not print the report to the screen
```

Both Python scripts exit with code `0` on success and `1` on failure, which is
what the shell scripts test to decide whether to continue.

---

## Error handling

The pipeline is written so that a user never sees a Python traceback:

* a missing input file, an empty file or a file with the wrong columns is
  reported as a plain message;
* a rolling window below one day is rejected before any file is opened;
* rows with blank fields, non-numeric text, sensor sentinel values such as
  `-999`, readings outside physically possible ranges, a minimum above the
  maximum, or a duplicate date are rejected by `clean_data.py`, which prints a
  count of each kind of problem;
* `weather_processor.py` skips any row it still cannot parse and reports how
  many were skipped, so it produces usable output even if it is pointed at a
  raw file directly;
* the shell scripts check that Python is installed and that the input file
  exists, and stop with a clear message if either stage fails.

`data/raw_weather_2025.csv` deliberately contains eight faulty rows so this
behaviour can be demonstrated.

## Requirements

Python 3.8 or newer. The programs use only the standard library (`csv`,
`math`, `os`, `sys`, `argparse`, `datetime`). PyInstaller is needed only to
build the executable.
